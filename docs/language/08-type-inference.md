# 8. 型推論とオーバーロードの解決

## 8.1 概要

**[INF-1]**

- 型推論は、区切り方の決定（[07](07-parsing.md)）と同時に、定義ごとに行います。
- すべての定義は型を宣言しているので、ある定義の推論は他の定義の推論結果に依存しません。他の定義は、宣言された型で参照します。
- 多相（型パラメータ）は定義の単位だけです。ラムダの引数は単相で、推論の結果を一般化して新しい型パラメータを作ることはありません。

## 8.2 型変数と具体化

**[INF-2]** 型変数には次の2種類があります。

- **固定の型変数**：推論中の定義の型パラメータ。特定の型として扱い、単一化できる相手は自分自身だけです。
- **推論中の型変数**：推論のために新しく作る型変数。単一化によって型が決まります。

**[INF-3]（具体化）** 型パラメータ T1 … Tm を持つ関数やコンストラクタを参照するたびに、その型の Ti を次のもので置き換えます。

- 型引数 `<τ1 … τm>` が書かれていれば τi。
- 書かれていなければ、新しい推論中の型変数 αi。

置き換えたもの（τi または αi）のレベルは次のとおりです。τi のレベルがこれと合わなければエラーです。

- 関数の型パラメータ：照合（[05](05-types.md) の [TYP-4]）で決まったレベルに、参照のレベル引数を代入したもの。固定レベル ‹Ti› だったものは不明。
- コンストラクタの型パラメータ：不明。

例：twice の T のレベルは (0, 0) ですが、lev(`-> int int`) = (1, 0) なので、`twice<-> int int>` はエラーです。

## 8.3 単一化

**[INF-4]** 単一化は通常の方法（出現検査を含む）で行い、それに加えてレベルを一致させます。

- 推論中の型変数 α を型 σ と単一化するとき、α のレベルが分かっていれば、lev(σ) と等しくなければなりません。lev(σ) の末尾が不明（σ の末尾が、レベルの分からない推論中の型変数）なら、等しくなるようにその型変数のレベルを決めます。決められなければエラーです。
- α のレベルが分からなければ、α のレベルは lev(σ) になります。
- 固定の型変数は、自分自身とだけ単一化できます。

例：レベル (2, 0) の α を `-> int β`（β のレベルは不明）と単一化すると、β のレベルは (1, 0) に決まります。レベル (0, 0) の α を `-> int β` と単一化することはできません。

## 8.4 型変数のレベルのまとめ

| 型変数 | レベル |
|---|---|
| 定義の型パラメータ | 照合で決まったもの。決まらなければ固定レベル ‹T› |
| 関数の参照で作った推論中の型変数 | 型パラメータのレベルにレベル引数を代入したもの（‹T› だったものは不明） |
| コンストラクタの参照で作った推論中の型変数 | 不明 |
| オーバーロードされた関数の参照で作った推論中の型変数（[INF-5]） | レベル宣言の対応する位置のもの |
| match の対象の型を分けるために作ったもの（[PAR-8]） | 不明 |
| 適用のために型を分けて作ったもの（[PAR-6]） | 引数の側は不明、残りの側は元のレベルの k から1を引いたもの |

レベルが不明な型変数のレベルは、単一化（[INF-4]）によって決まります。

## 8.5 オーバーロードの解決

**[INF-5]** オーバーロードされた関数 f を参照するたびに、次のことを行います。

1. f のレベル宣言（レベル引数を代入したもの）の矢印の数を n として、型 `-> α1 -> … -> αn ρ` を作ります。αi と ρ は新しい推論中の型変数で、レベルはレベル宣言の対応する位置の lev です。これがこの参照の型です。
2. この参照の**候補**は、f のすべての定義です。
3. 単一化を行うたびに、各候補について「その定義の型（型パラメータを新しい推論中の型変数に置き換えたもの）が、この参照の型と単一化できるか」を調べ、できない候補を除きます。
4. 候補が1つになったら、その定義に確定し、その定義の型とこの参照の型を単一化します。確定によってさらに単一化が起これば、3 から繰り返します。
5. 候補が0個になったらエラーです。

**[INF-6]** 候補は除かれるだけで増えることはないので、複数の参照の確定の順序が結果を変えることはありません。区切り方の判断（[07](07-parsing.md)）は、その時点で確定している情報を使います（[PAR-9]）。

## 8.6 定義の終わりの検査

**[INF-7]** 定義の本体を読み終えた時点で、次を検査します。

- 本体の型が、宣言された型と単一化されていること（[PAR-4] の「止まったら単一化」で行われる）。
- 未解決の推論中の型変数が残っていないこと。
- 確定していないオーバーロードの参照が残っていないこと。

残っていればエラーです。たとえば `length Nil` は、Nil の型引数が決まらないのでエラーです。`length Nil<int>` と書きます。

## 8.7 明示的な型引数

**[INF-8]** 型引数 `< >` は、推論を助けるために書けます（[06](06-expressions.md) の [EXP-1]）。全部指定するか全部省略します。書いた型引数は [INF-3] で使います。型引数を書くと、コンストラクタのフィールドなどの期待レベルが決まるので、区切り方が変わることがあります。

```
length Cons<int> + 1 2 Nil         // フィールドは int（レベル0）なので + 1 2 を読む
length Cons<-> int int> + 1 Nil    // フィールドはレベル1なので + 1（部分適用）を読む
```
