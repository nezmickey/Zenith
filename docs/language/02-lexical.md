# 2. 字句

字句解析は、ソースを**語**に分けるところまでを行います。語のどこまでが名前で、どこからがレベル引数・型引数なのかは、宣言された名前の表を使って決めます（2.7）。Zenith では字句と構文が密接に結びついているので、この章の一部は構文解析の段階で使われます。

## 2.1 ソースの文字

**[LEX-1]** ソースは UTF-8 で書かれたテキストです。ASCII 以外の文字は、文字列リテラルとコメントの中にだけ書けます。それ以外の場所にある ASCII 以外の文字（全角スペースを含む）はエラーです。

**[LEX-2]** 文字は次のように分類します。

| 分類 | 文字 |
|---|---|
| 空白 | スペース（U+0020）、タブ（U+0009）、CR（U+000D）、LF（U+000A） |
| 区切り文字 | `;` |
| 予約文字 | `[` `]` |
| 一般の文字 | 上記以外の印字可能な ASCII 文字（U+0021〜U+007E） |

空白以外の制御文字は、文字列リテラルとコメントの外ではエラーです。

## 2.2 語への分割

**[LEX-3]** ソースは、空白と `;` で**語**に分けます。`;` はそれ自体が1つのトークンで、前後に空白がなくてもかまいません（`x;` は語 `x` とトークン `;`）。

**[LEX-4]** 語の先頭では、次の場合を特別に扱います。

| 語の先頭 | 扱い |
|---|---|
| `"` | 文字列リテラル（2.4）。閉じる `"` まで読む |
| `//` | コメント。行末（LF）または入力の終わりまで |
| `/*` | コメント。最初に現れる `*/` まで。入れ子にはならない |

- 語の途中にある `"`、`//`、`/*` は、その語の一部です（`a//b` は1つの語）。
- 閉じていない `/*` と、閉じていない文字列リテラルはエラーです。
- コメントは空白と同じく語を区切ります。

**[LEX-5]** 文字列リテラルの直後は、空白・`;`・コメント・入力の終わりのどれかでなければなりません（`"a"b` はエラー）。

## 2.3 予約語

**[LEX-6]** 次の語は予約語で、名前として使えません。

```
type  match  \  =  ->  :  ::  true  false  int  double  bool  string
```

- 予約語は、語全体が一致したときだけ予約語です。`==`、`->>`、`matchx`、`\x`、`x:` などは名前になれます。
- `\` と `match` には、レベル区域（2.6）を直接付けられます（`\[1]`、`match[1]`）。
- `|` は、type 宣言の中でだけ区切りの記号です（[03](03-program.md) の 3.2）。式の中では普通の名前です。

## 2.4 リテラル

### 数値

```
sign           ::= "+" | "-"
digits         ::= [0-9]+
exponent       ::= ( "e" | "E" ) sign? digits

int-literal    ::= sign? digits
double-literal ::= sign? digits ( "." digits exponent? | exponent )
```

**[LEX-7]** 次のどれかで始まる語は、その語全体が `int-literal` か `double-literal` でなければなりません（そうでなければエラー）。

- 数字
- `.` に続く数字
- 符号に続く数字
- 符号と `.` に続く数字

| 語 | 読み方 |
|---|---|
| `0` `-0` `+0` `37` `-49` `+32` `007` | 整数リテラル |
| `1.5` `-0.01` `1.0e300` `1.0e-300` `-3.7e+50` `30e6` `10E3` | 小数リテラル |
| `3.` `.5` `1e` `1.0e+` `3e2.5` `2x` `-1x` | エラー |
| `-x` `+x` `-` `+` `.` `.x` | 名前 |

**[LEX-8]** 整数リテラルの型は int です。値は10進数として読み、先頭の 0 も許します。値が int（64ビット符号付き整数）の範囲外ならエラーです。

**[LEX-9]** 小数リテラルの型は double です。値は、書かれた10進数に最も近い double（IEEE 754 倍精度）に丸めます。丸めた結果が無限大になる場合はエラーです。

**[LEX-10]** 整数リテラルは常に int です。文脈や型推論によって double として扱われることはありません（[05](05-types.md) の [TYP-7]）。

### 文字列

```
string-literal ::= '"' ( 文字 | escape )* '"'
escape         ::= '\"' | '\\' | '\n' | '\t'
```

（この2行に限り、`"` を含む終端記号を `' '` で囲んで書いています。）

**[LEX-11]** 文字列リテラルの型は string です。

- エスケープは `\"`（`"`）、`\\`（`\`）、`\n`（LF）、`\t`（タブ）の4つだけです。それ以外の `\` で始まる並びはエラーです。
- 改行（LF、CR）を直接含めることはできません。
- ASCII 以外の文字は、UTF-8 のまま含められます。

### 真偽値

**[LEX-12]** `true` と `false` は bool のリテラルです。

## 2.5 名前

**[LEX-13]** 名前には一般の文字（[LEX-2]）を使えます。ただし次のものは名前になれません。

- 予約語ちょうどの語（[LEX-6]）
- 数値のように見える語（[LEX-7]）
- `"`、`//`、`/*` で始まる語（文字列やコメントになるため。[LEX-4]）

**[LEX-14]** 名前の種類ごとに、次の制限が加わります。

| 種類 | 追加の制限 |
|---|---|
| 値の名前（関数・コンストラクタ・局所変数） | コンストラクタ名は `\|` ちょうどにできない |
| 型名・型変数名・レベル変数名 | `<` と `>` を含められない。`\|` ちょうどにできない |

値の名前には `<` `>` `:` `=` なども使えます（`vec+`、`<<`、`a<b`、`:>`）。

## 2.6 区域

名前の直後には、空白を挟まずに**レベル区域**と**型区域**を付けられます。

```
name-word    ::= NAME level-region? type-region?
level-region ::= "[" ( NAT | LVAR )* "]"
type-region  ::= "<" type+ ">"
```

**[LEX-15]** レベル区域は `[` から対応する `]` までです。中に空白を含んでよく、複数の語にまたがります。中身は、空白で区切った符号なしの数字列（`NAT`）またはレベル変数名です。0個でもかまいません（`[]`）。どこに何を書けるかは [03](03-program.md)・[04](04-levels.md)・[06](06-expressions.md) で定めます。

**[LEX-16]** 型区域は `<` から対応する `>` までです。中身は型の並びで、2.8 の方法で読みます。複数の語にまたがってかまいません。

**[LEX-17]** 区域の後ろで語は終わります（`f[1]x`、`list<int>x` はエラー）。名前と区域の間、レベル区域と型区域の間に空白は入れられません。

## 2.7 名前の範囲の決め方

値の名前は `<` を含められるので、`a<b>` のような語が「名前 `a<b>`」なのか「名前 `a` と型区域 `<b>`」なのかは、どの名前が宣言されているかで決まります。

**[LEX-18]（参照の位置）** 式の中の語は、次の順に解釈します。

1. 語全体が、その位置で見えている名前なら、その名前です。
2. そうでなければ、語の先頭部分のうち、見えている名前に一致し、かつ直後が `[` か `<` であるものを探し、最も長いものを名前とします。残りは区域として読みます。予約語の `\` と `match` も、直後が `[` の場合はここで一致します。
3. どちらにも当てはまらなければ、未定義の名前としてエラーです。

**[LEX-19]（宣言の位置）**

| 位置 | 名前の範囲 |
|---|---|
| `::` の左 | 最初の `[` の手前まで（`<` を含んでもよい） |
| `:` の左 | [LEX-18] と同じ方法で、`::` で宣言された名前（組み込みを含む）と照らし合わせて決める |
| type 宣言の型名 | 最初の `<` の手前まで |
| コンストラクタ名 | 語全体 |
| ラムダの引数、パターンの束縛変数 | 語全体 |

**[LEX-20]（衝突の禁止）** 型パラメータを持つ値の名前 m が見えているとき、`m<` で始まる別の値の名前が同時に見えていてはなりません。

- 関数は、定義（`:`）のどれか1つでも型パラメータを持てば「型パラメータを持つ」とみなします。コンストラクタは、その型が型パラメータを持てば該当します。
- 大域名どうしは、すべての定義の見出しを読み終えた時点で検査します（[03](03-program.md) の 3.6 の段階 1b）。局所変数は、束縛した時点で検査します。
- 型パラメータを持たない名前には、この制限はありません。たとえば組み込みの `<` は型パラメータを持たないので、`<<` という名前を定義できます。

## 2.8 型の位置の読み方

型は、`:` の右、ラムダの型注釈、type 宣言のフィールド、型区域の中に現れます。型の位置では、名前の表を使わずに次のように読みます。

**[LEX-21]**

- 語の先頭、または `<` の直後にある `->` は、関数型の矢印です。矢印の直後は空白でなければなりません。
- それ以外では、`<` `>` `[` `]` `;` と空白以外の文字の最も長い並びを、1つの型名（または型変数名）として読みます。
- 型名の直後の `<` は、その型の型区域の始まりです。`>` は、いま読んでいる型区域の終わりです。

例：`Cons<-> int int>` は、名前 `Cons`、型区域の始まり、矢印、`int`、`int`、型区域の終わり、と読みます。`pair<int list<int>>` の最後の `>>` は、2つの型区域の終わりです。

## 2.9 例

| ソース | 読み方 |
|---|---|
| `twice<int>` | `twice<int>` という名前がなければ、名前 `twice` と型区域 `<int>` |
| `a<b` | `a<b` という名前が宣言されていれば、その名前 |
| `head[N M]` | 名前 `head` とレベル区域 `[N M]`（語 `head[N` と `M]` にまたがる） |
| `if[0]` | 名前 `if` とレベル区域 `[0]` |
| `\[1]` | ラムダの `\` とレベル区域 `[1]` |
| `++<int>` | `++<int>` という名前がなければ、名前 `++` と型区域 `<int>` |
| `x;` | 名前 `x` と区切り `;` |
| `-1` `+3` | 整数リテラル |
| `-x` | 名前（符号反転ではない。符号反転は `- 0 x` と書く） |
| `3.` | エラー |
| `\x` | 名前（ラムダは `\ x` と書く） |
| `/ * p` | 名前 `/`、名前 `*`、名前 `p`（`/*` と続けて書くとコメントの開始になる） |
