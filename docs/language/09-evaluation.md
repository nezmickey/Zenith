# 9. 評価

評価の意味は Core（[12](12-core.md)）の上で定めます。Zenith のプログラムは Core に変換され、Core のプログラムとして評価されます。

## 9.1 遅延評価

**[EVL-1]** Zenith は遅延評価（必要渡し、call-by-need）です。

- 関数に渡す引数は、評価されないまま**サンク**（未評価の計算）として渡されます。
- サンクは、その値が必要になったときに初めて評価され、結果は記録されます。同じサンクが2回評価されることはありません（共有）。
- 値は**弱頭部正規形**まで評価されます。関数の値（ラムダ、部分適用）、コンストラクタを適用した値（フィールドはサンクのまま）、リテラルの値がこれに当たります。

## 9.2 各構文の評価

**[EVL-2]**

| Core の形 | 評価 |
|---|---|
| リテラル | その値 |
| 局所変数 | 束縛されたサンクを評価した値 |
| 関数の参照 `f⟨τ…⟩`、`⟦f : τ⟧` | その定義（選択された定義）の本体を評価した値 |
| コンストラクタ `C⟨τ…⟩` | フィールドの数だけ引数を受け取ると、コンストラクタを適用した値になる関数の値（フィールドが0個なら、そのままコンストラクタの値） |
| `⟦f a1 … an⟧` | f を評価して関数の値を得て、a1 … an をサンクとして順に渡す |
| `⟦\ x : τ e⟧` | 関数の値。適用されると、x を引数のサンクに束縛して e を評価する |
| `⟦match s ⟦C x… ⇒ e⟧ …⟧` | s を評価してコンストラクタを適用した値を得る。そのコンストラクタの分岐を選び、束縛変数をフィールドのサンクに束縛して、本体を評価する |

**[EVL-3]** 引数を取らない大域定義（レベル宣言が `0` の定義）を一度だけ評価して共有するかどうかは、実装に任せます。意味としては区別できません。

## 9.3 ローカル変数と共有

ラムダをその場で適用する形（[06](06-expressions.md) の 6.3）では、束縛される値は1つのサンクになります。本体の中で何回使われても、評価は1回だけです。

```
\ sq : int * sq sq * x x      // * x x は1回だけ評価される
```

同じ引数で関数を呼んだ結果を覚えておく（メモ化）ことはしません。

## 9.4 組み込みの名前の評価

**[EVL-4]**

- 算術・比較・変換の組み込み関数は、すべての引数を評価してから計算します。引数を評価する順序は規定しません。
- `if` は条件を評価し、選ばれた側の引数だけを評価します。選ばれなかった側は評価しません。
- `error` は引数の文字列を評価して出力し、プログラムを終了します。文字列の評価中に別の `error` が評価された場合は、そちらが出力されて終了します。

遅延評価なので、`if` を使って定義した関数（`unless` など）も、選ばれなかった側を評価しません。

```
unless[N] :: -> 0 -> N -> N N;
unless[N]<T> : -> bool -> T -> T T = \ c : bool \ a : T \ b : T if[N] c b a;
```

各組み込み関数の意味は [10](10-builtins.md) で定めます。

## 9.5 プログラムの評価

**[EVL-5]** プログラムの実行は、main をコマンドラインの引数に適用した式を評価し、その結果を出力することです（[11](11-program-io.md)）。

## 9.6 規定していないこと

次の場合の動作は、現時点では規定しません（実装の動作に任せます）。

- int のゼロ除算と、int の演算のオーバーフロー（`INT64_MIN / -1` を含む）
- 終わらない計算、深い再帰によるスタックの不足
- 評価されうる `error` が複数あるとき、どれが出力されるか（組み込み関数の引数の評価順序に依存する場合）

実行時エラーの扱い（メッセージ、呼び出し元の出力など）は未決です（[appendix/c](appendix/c-open-issues.md)）。
