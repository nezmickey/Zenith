# 3. プログラムと文

## 3.1 プログラム

```
program ::= stmt*
stmt    ::= type-decl | level-decl | def
```

プログラムは文の並びです。文は型宣言・レベル宣言・定義の3種類で、どれも `;` で終わります。

**[PRG-1]** 文の順序は自由です。どの文も、プログラム中のすべての宣言を参照できます（相互再帰を含む）。

**[PRG-2]** 文の種類は次のように決めます。

- 最初の語が `type` なら型宣言です。
- そうでなければ、`;` までの語のうち最初に現れる `::` または `:` という語で決めます。`::` ならレベル宣言、`:` なら定義です。
- どちらも現れなければエラーです。

## 3.2 型宣言

```
type-decl ::= "type" TNAME ( "<" TVAR+ ">" )? "=" alt+ ";"
alt       ::= "|" CTOR type*
```

```
type money    = | Yen int;
type discount = | NoDiscount | Percent int | Fixed money;
type list<T>  = | Nil | Cons T list<T>;
```

型宣言は、代数的データ型と、そのコンストラクタを作ります（[05](05-types.md) の 5.3）。

**[PRG-3]**

- 型名はプログラム全体で一意です。組み込みの型名（`int` など）は予約語なので使えません。
- 型パラメータの名前は互いに異なり、既存の型名と同じにはできません。
- 選択肢（`alt`）は1つ以上必要で、それぞれ `|` で始まります。選択肢のフィールドの並びは、次の `|` か `;` で終わります。
- フィールドの型に使える型変数は、その型宣言の型パラメータだけです。
- 再帰的な型や、互いに参照し合う型を宣言できます。

**[PRG-4]**

- コンストラクタ名はプログラム全体で一意で、関数名（組み込みを含む）と重なってはなりません。
- コンストラクタにはレベル宣言を書けません。コンストラクタのレベルはフィールドの数です（[04](04-levels.md)）。
- コンストラクタ名を大文字で始めるのは慣習で、規則ではありません。

## 3.3 レベル宣言

```
level-decl ::= NAME ( "[" LVAR* "]" )? "::" level ";"
```

```
twice :: -> 1 -> 0 0;
head[N] :: -> 0 N;
```

**[PRG-5]**

- 関数の名前ごとに、レベル宣言はちょうど1つです。
- 組み込みの名前とコンストラクタには、レベル宣言を書けません。
- レベルパラメータの名前は互いに異なります。
- `level` の文法と意味は [04](04-levels.md) で定めます。

## 3.4 定義

```
def ::= NAME ( "[" LVAR* "]" )? ( "<" TVAR+ ">" )? ":" type "=" expr ";"
```

```
twice<T> : -> -> T T -> T T = \ f : -> T T \ x : T f f x;
head[N]<T> : -> list<T> T = \ xs : list<T> match xs Nil error[N] "head: 空リスト" Cons x _ x;
```

**[PRG-6]**

- 定義する名前には、レベル宣言がなければなりません（組み込みの名前を除く）。
- レベル宣言があって定義が1つもない名前はエラーです。
- レベルパラメータは、レベル宣言と同じ名前を同じ順に書きます。
- 型パラメータは定義ごとに書きます。名前は互いに異なり、既存の型名と同じにはできません。
- 定義の型とレベル宣言は、照合できなければなりません（[05](05-types.md) の 5.6）。
- 本体 `expr` は [07](07-parsing.md) の規則で読みます。本体を読み終えたら、次のトークンは `;` でなければなりません。

**[PRG-7]（オーバーロード）** 同じ名前に定義を複数書けます（オーバーロード）。

- レベル宣言は1つだけで、すべての定義が共有します。
- 同じ名前の定義どうしは、型が単一化できてはなりません。型パラメータを新しい推論中の型変数に置き換えて単一化を試み、成功したらエラーです。たとえば `-> int int` と `-> T T` は並べて書けません。
- 組み込みの名前にも定義を追加できます。追加した定義も、組み込みのレベル宣言と照合でき、他の定義と型が重なってはなりません。

## 3.5 名前空間とスコープ

**[PRG-8]** 名前空間は次の3つで、互いに独立です。

| 名前空間 | 含むもの |
|---|---|
| 値 | 関数（組み込みを含む）、コンストラクタ、局所変数 |
| 型 | 型名、型変数 |
| レベル | レベル変数 |

**[PRG-9]（スコープ）**

- 関数とコンストラクタは、プログラム全体から見えます。
- 局所変数は、それを導入したラムダの本体、または match の分岐の本体の中だけで見えます。内側の局所変数は、外側の同じ名前（大域名を含む）を隠します。
- コンストラクタ名は、局所変数の名前にできません。
- 型パラメータは、その定義（`:` の型と本体）または型宣言の中だけで見えます。
- レベルパラメータは、そのレベル宣言と、同じ名前の定義（見出し・型・本体）の中だけで見えます。

## 3.6 処理の段階

名前の範囲を宣言の表で決める（[02](02-lexical.md) の 2.7）ため、処理は次の段階に分かれます。各段階は、それより前の段階の結果だけを使います。

| 段階 | 行うこと | 使う名前の表 |
|---|---|---|
| 1a | 文の切り出しと種類の判定。レベル宣言（名前とレベル式）。型宣言（型名、コンストラクタ名、フィールドの型） | なし |
| 1b | 定義の見出し（名前・レベルパラメータ・型パラメータ）と型。照合。[LEX-20] の衝突、名前の重複、オーバーロードの型の重なりの検査 | 1a の表 |
| 2 | 各定義の本体（区切り方の決定と型推論） | 1a と 1b の表 |

段階 1a で使うのは、文字列リテラルとコメントの認識（[LEX-4]）、`;`、型の位置の読み方（[LEX-21]）だけなので、名前の表は要りません。

## 3.7 main

プログラムを実行するには、`main` という名前の関数が必要です。`main` の型と入出力は [11](11-program-io.md) で定めます。
