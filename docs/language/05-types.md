# 5. 型

## 5.1 型の種類

| 型 | 意味 | 最初の実装（C++）での表現 |
|---|---|---|
| `int` | 64ビット符号付き整数 | `int64_t` |
| `double` | IEEE 754 倍精度浮動小数点数 | `double` |
| `bool` | 真偽値 | `bool` |
| `string` | 文字列 | `std::string` |
| `-> A B` | A を受け取り B を返す関数 | |
| `D<τ…>` | 型宣言で作った代数的データ型 | |
| 型変数 | 定義または型宣言の型パラメータ | |

関数は1引数です。複数の引数を取る関数は、関数を返す関数として表します（カリー化）。`-> int -> int int` は「int を取り、`-> int int` を返す関数」です。

## 5.2 型式

```
type   ::= "->" type type | tatom
tatom  ::= "int" | "double" | "bool" | "string"
         | TNAME ( "<" type+ ">" )?
         | TVAR
```

**[TYP-1]**

- 型の位置の語は [02](02-lexical.md) の [LEX-21] で読みます。
- `TNAME` は宣言された型名、`TVAR` はその位置で見えている型変数です（[03](03-program.md) の [PRG-9]）。
- 型名に付ける型引数の数は、その型のパラメータの数とちょうど同じでなければなりません（`list` だけ、`list<int int>` はエラー）。

## 5.3 代数的データ型とコンストラクタ

型宣言 `type D<T1 … Tm> = | C F1 … Fn | …;` は、型 `D<T1 … Tm>` とコンストラクタ C を作ります。

**[TYP-2]** コンストラクタ C の型は `-> F1 … -> Fn D<T1 … Tm>` です（n = 0 なら `D<T1 … Tm>`）。T1 … Tm は C の型パラメータです。C のレベルは (n, 0) です。

```
type list<T> = | Nil | Cons T list<T>;
// Nil  の型は list<T>
// Cons の型は -> T -> list<T> list<T>、レベルは (2, 0)
```

## 5.4 型変数のスコープ

**[TYP-3]**

- 型変数を導入できるのは、定義の `< >` と型宣言の `< >` だけです。
- ラムダの型注釈や、式の中の型引数に書ける型変数は、外側の定義が導入したものだけです。ラムダは新しい型変数を導入しません（ラムダの引数は単相）。

## 5.5 型のレベル

型のレベルは [04](04-levels.md) の [LVL-3] の lev で決まります。たとえば lev(`-> int -> int int`) = (2, 0)、lev(`-> -> int int -> int int`) = (2, 0) です。型変数のレベルは 5.6 と [08](08-type-inference.md) の 8.4 で決まります。

## 5.6 照合

**照合**は、レベル宣言と定義の型を突き合わせて、定義の型パラメータのレベルを決める操作です。

**[TYP-4]** レベル宣言のレベル式 ℓ と、定義の型 σ を、次の表に従って突き合わせます。

| ℓ | σ | 結果 |
|---|---|---|
| `0` | 基本型、代数的データ型 | 成功 |
| `0` | 型パラメータ T | T のレベルは (0, 0) |
| `N`（レベル変数） | 型パラメータ T | T のレベルは (0, N) |
| 引数位置の `k` | `-> A1 … -> Am R`（m ≥ 0、R は矢印でない） | m = k なら、R は基本型・代数的データ型か、型パラメータ（そのレベルを (0, 0) とする）でなければならない。m < k なら、R は型パラメータでなければならず、そのレベルを (k − m, 0) とする。m > k はエラー |
| `-> ℓ1 ℓ2` | `-> σ1 σ2` | ℓ1 と σ1、ℓ2 と σ2 をそれぞれ照合する |
| それ以外 | | エラー |

- 同じ型パラメータに異なるレベルが付いたらエラーです。
- 引数位置の `k` に対応する型の、内側の引数（A1 … Am）は照合しません。代数的データ型の型引数の中（`list<T>` の T）も照合しません。
- 関数の形のレベル式（`-> ℓ1 ℓ2`）に型パラメータを対応させることはできません（表の「それ以外」）。

**[TYP-5]（固定レベル）** 照合でレベルが決まらなかった型パラメータ T には、T 専用の固定レベル ‹T› を割り当てます。T のレベルは (0, ‹T›) です。定義の本体の中では、型 T の値は受け渡すことしかできません。適用することも、レベル0を求める位置に置くこともできません（[07](07-parsing.md) の [PAR-4] でエラーになる）。

| レベル宣言 | 型 | 型パラメータのレベル |
|---|---|---|
| `twice :: -> 1 -> 0 0` | `-> -> T T -> T T` | T：(0, 0) |
| `head[N] :: -> 0 N` | `-> list<T> T` | T：(0, N) |
| `unless[N] :: -> 0 -> N -> N N` | `-> bool -> T -> T T` | T：(0, N) |
| `length :: -> 0 0` | `-> list<T> int` | T：‹T› |
| `map :: -> 1 -> 0 0` | `-> -> A B -> list<A> list<B>` | A：‹A›、B：(0, 0) |
| `map[N] :: -> -> N 0 -> 0 0` | `-> -> A B -> list<A> list<B>` | A：(0, N)、B：(0, 0) |

## 5.7 オーバーロード

**[TYP-6]**

- 同じ名前の定義は、1つのレベル宣言を共有します（[03](03-program.md) の [PRG-7]）。各定義の型は、それぞれそのレベル宣言と照合できなければなりません。
- 同じ名前の定義どうしの型は、単一化できてはなりません。
- オーバーロードされた名前（定義が2つ以上ある名前）を参照するときは、型区域 `< >` を付けられません。どの定義を使うかは型推論で決めます（[08](08-type-inference.md) の 8.5）。
- レベル宣言は共有されているので、オーバーロードされた名前にもレベル区域 `[ ]` は付けられます。

## 5.8 暗黙の変換はない

**[TYP-7]** 型の暗黙の変換はありません。整数リテラルは常に int で（[02](02-lexical.md) の [LEX-10]）、int の値が double として扱われることもありません。`+ 1 2.0` は、int と double を受け取る `+` の定義がない限り型エラーです。変換には `to_double` などの関数を使います（[10](10-builtins.md)）。
