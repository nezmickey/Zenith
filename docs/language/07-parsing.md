# 7. 式の読み方

この章では、式の区切り方（各頭がいくつの引数を取るか、match がいくつの分岐を持つか）を決める規則を定めます。区切り方の決定は、型推論（[08](08-type-inference.md)）と同時に行います。

## 7.1 概要

区切り方は、次の原則で決まります。

| 頭の種類 | 何個の引数を取るかを決めるもの |
|---|---|
| **名前**（関数、コンストラクタ） | 関数はレベル宣言 `::` とレベル引数 `[ ]`、コンストラクタはフィールドの数 |
| **値**（局所変数、式の結果） | その時点で分かっている型 |
| 期待レベルが分からない位置に置かれたもの | 何も取らない（その項をそのまま置く） |

- 区切り方は左から順に決め、後戻りはしません。
- 判断に使うのは、それより左にある語、外側から与えられる期待、宣言の表、その時点までの推論結果だけです。
- ラムダと match の本体のレベルは、「明示（`[k]`）＞ 文脈 ＞ 既定値の0」の順で決まります。

## 7.2 期待

**[PAR-1]** 式は、**期待** ε = ⟨τ, ℓ⟩ のもとで読みます。τ はその位置で求められる型、ℓ = (k, t) はレベルの値です（[04](04-levels.md) の [LVL-3]）。τ は推論中の型変数を含んでいてもかまいません。

## 7.3 定義の本体

**[PAR-2]** 定義 `f[Ls]<Ts> : σ = e;` の本体 e は、⟨σ, lev(ℓf)⟩ で読みます。ℓf は f のレベル宣言のレベル式です。本体の中では、Ts は固定の型変数、Ls は固定のレベル変数です。

## 7.4 頭の型とレベル

**[PAR-3]** 式は、頭を1つ読むことから始まります。頭の型とレベルは次のとおりです。

| 頭 | 型 | レベル |
|---|---|---|
| 整数・小数・文字列・真偽値のリテラル | `int`・`double`・`string`・`bool` | (0, 0) |
| 局所変数 | 束縛されたときの型 | その型の lev |
| 関数（オーバーロードなし） | 定義の型を具体化したもの（[08](08-type-inference.md) の [INF-3]） | レベル宣言にレベル引数を代入したものの lev |
| 関数（オーバーロードあり） | レベル宣言の形に合わせて作った型（[08](08-type-inference.md) の [INF-5]） | 同上 |
| コンストラクタ | 型（[05](05-types.md) の [TYP-2]）を具体化したもの | (n, 0)（n はフィールドの数） |
| ラムダ | 7.6 | 7.6 |
| match | 7.7 | 7.7 |

## 7.5 適用

**[PAR-4]** 頭 h を読んだ後、h の型を ρ、レベルを ℓh = (kh, th)、期待を ⟨τ, ℓ = (k, t)⟩ として、次を上から順に調べることを繰り返します。

1. t が不明 → 止まる。
2. th と t がどちらも分かっていて、異なる → エラー。
3. kh > k → 引数を1つ読む（[PAR-6]）。h を「h にその引数を適用したもの」に置き換えて、1 に戻る。
4. kh = k → 止まる。
5. th が不明 → 止まる。
6. それ以外 → エラー。

止まったら、ρ と τ を単一化します（レベルも一致させる。[08](08-type-inference.md) の [INF-4]）。

**[PAR-5]（外側からの情報）** 1 を始める前に、th と t がどちらも分かっていて kh ≥ k なら、取る引数の数 n = kh − k が決まります。このときは、ρ から引数を n 個外した残りの型を、引数を読む前に τ と単一化します。外すために型を分ける必要があれば、[PAR-6] と同じ方法で分けます。

**[PAR-6]（引数の期待）** 次に読む引数の期待は、次のように決めます。

- h がレベル宣言を持つ関数で、そのレベル式の矢印をまだ使い切っていないとき：その位置の `arg-level`（レベル引数を代入したもの）の lev と、h の型のその位置の引数の型。
- それ以外のとき：その時点の ρ について、
  - ρ が `-> A B` なら、⟨A, lev(A)⟩。
  - ρ が推論中の型変数で、そのレベルが (j, t′)（j ≥ 1）と分かっていれば、ρ を `-> β γ` と単一化して分けます。β は新しい推論中の型変数でレベルは不明、γ は新しい推論中の型変数でレベルは (j − 1, t′) です。期待は ⟨β, (0, ?)⟩ です。
  - それ以外（固定の型変数など）はエラーです。

引数は、その期待のもとで式として読みます。

## 7.6 ラムダ

**[PAR-7]** ラムダ `\[k]? x : τx body` を期待 ⟨τ, ℓ = (k′, t)⟩ のもとで読みます。

1. τx を型として読みます。x の型は τx、レベルは lev(τx) です。
2. ℓ によって、次のどれかに決まります。

| ℓ | ラムダの扱い | 本体の期待レベル b | 型の扱い |
|---|---|---|---|
| k′ = 0 で、t が分かっている | その場で適用される | (0, t) | 本体の期待型は τ。ラムダの型は `-> τx τ` |
| k′ ≥ 1（t は不明でもよい） | 関数として置く | (k′ − 1, t) | τ を `-> τx ρ`（ρ は新しい推論中の型変数）と単一化し、本体の期待型は ρ |
| k′ = 0 で、t が不明 | 関数として置く | (0, ?) | 本体の期待型は新しい推論中の型変数 ρ。ラムダの型は `-> τx ρ` |

3. `[k]` が書かれていれば、b を `[k]` の値（`NAT` の k なら (k, 0)、レベル変数 N なら (0, N)）に置き換えます。ただし、置き換える前の b と矛盾するならエラーです。
   - b の末尾が分かっているとき：`[k]` の値が b と等しくなければ矛盾です。
   - b = (j, ?) のとき：`[k]` の値が (m, 0) で m < j なら矛盾です。`[k]` の値が (0, N) で j ≥ 1 なら矛盾です。
4. `[k]` がなく、b の末尾が不明なら、末尾を 0 とします（b = (j, ?) なら (j, 0)）。
5. 本体を ⟨本体の期待型, b⟩ で読みます。x は本体の中だけで見えます。
6. ラムダを頭として 7.5 の適用の規則を続けます。ラムダのレベルは、b の k に 1 を足したものです。「その場で適用される」場合は、ここで引数を1つ読むことになります。

| 位置 | 書き方 | 読み方 |
|---|---|---|
| `twice<int>` の第1引数（期待レベル (1, 0)） | `\ x : int + x 1` | 関数。本体はレベル0 |
| レベル0の位置 | `\ s : int + s 1 * n n` | その場で適用。s = `* n n` |
| `add : -> int -> int int` の本体（期待レベル (2, 0)） | `\ a : int \ b : int + a b` | 外側は関数で、本体はレベル1。内側も関数で、本体はレベル0 |
| レベル N の位置（`[N]` を持つ定義の中） | `\ big : bool if[N] big a b >= n 100` | その場で適用。big = `>= n 100` |
| 期待レベルが完全に不明 | `\ x : int + x n` | 関数。本体は既定値のレベル0 |
| 期待レベルが完全に不明 | `\[1] x : int + x` | 関数。本体はレベル1 |
| 期待型が `-> int β`（β のレベルは不明、期待レベル (1, ?)） | `\ x : int + x 1` | 関数。本体は (0, ?) で、末尾を0として (0, 0) |
| 同上 | `\ x : int \ y : int + x y` | 外側の本体が (0, 0) になるので、内側のラムダがその場で適用されてしまう。`\[1] x : int \ y : int + x y` と書く |
| `twice<int>` の第1引数 | `\[1] x : int + x 1` | エラー（文脈では本体はレベル0） |

**関数を返すラムダ**：期待レベルの末尾が分からない位置に、関数を返すラムダ（本体のレベルが1以上のラムダ）を置くときは、`\[k]` で本体のレベルを明示します。

**関数を返す位置のローカル変数**：期待レベルの k が1以上の位置では、ラムダは常に関数として置かれるので、そこでラムダをその場で適用する（ローカル変数を作る）ことはできません。共有したい値は、補助関数の引数として渡します。

## 7.7 match

**[PAR-8]** `match[k]? s branch…` を期待 ⟨τ, ℓ⟩ のもとで読みます。

1. s を ⟨α, (0, 0)⟩ で読みます（α は新しい推論中の型変数）。
2. 次の語は、型宣言されたコンストラクタでなければなりません。その型を D とし、α を `D<β1 … βm>` と単一化します（βi は新しい推論中の型変数で、レベルは不明）。
3. 分岐の本体の期待レベル b は ℓ です。`[k]` が書かれていれば、[PAR-7] の 3 と同じ方法で置き換えます。`[k]` がなく、b の末尾が不明なら、末尾を 0 とします。
4. D のコンストラクタの数だけ分岐を読みます。各分岐では、
   - まだ使っていない D のコンストラクタ C を読みます（使用済みのもの、D 以外のものはエラー）。
   - C のフィールドの数だけ束縛変数を読みます。束縛変数の型は、C のフィールドの型の型パラメータに βi を代入したもの、レベルはその型の lev です。
   - 本体を ⟨τ, b⟩ で読みます。
5. match の型は τ、レベルは b です。7.5 の適用の規則では、ここで止まります（match は引数を取らない）。

束縛変数の型は対象の式の型から決まるので、パターンに型引数やレベル引数を書く必要はありません。たとえば `head[N]` の本体（7.10）では、対象 `xs` の型が `list<T>` なので、`Cons x _` の x の型は T（レベル (0, N)）になります。

## 7.8 型推論との関係

**[PAR-9]** 区切り方の決定と型推論は1つの処理です。

- 7.5〜7.7 の単一化は、その場で行います。単一化はレベルも一致させるので、区切り方の決定で置いた仮定（「何も取らない」「末尾を0とする」など）が、後で分かった型やレベルと矛盾すれば、必ずエラーになります。
- 単一化を行うたびに、候補が1つに絞られたオーバーロードを確定させます（[08](08-type-inference.md) の [INF-5]）。区切り方の判断には、その時点で確定している情報を使います。

## 7.9 決定性

**[PAR-10]** 区切り方は一意に決まります。各判断は、それより左の語、外側から与えられた期待、宣言の表、その時点までの推論結果だけで決まり、後戻りはしません。

ただし、規則どおりの区切り方が型としても成り立てば、それが書いた人の意図と違っていてもエラーにはなりません。

## 7.10 例

### twice を使う main

```
main :: -> 0 0;
main : -> int int = \ x : int twice<int> ++ * x x;
```

| 手順 | 読む語 | 期待 | 判断 |
|---|---|---|---|
| 1 | （本体） | ⟨`-> int int`, (1, 0)⟩ | main のレベル宣言は `-> 0 0` |
| 2 | `\ x : int` | ⟨`-> int int`, (1, 0)⟩ | k′ = 1 なので関数。`-> int ρ` との単一化で ρ = int。本体は ⟨int, (0, 0)⟩ |
| 3 | `twice<int>` | ⟨int, (0, 0)⟩ | 関数。レベル宣言 `-> 1 -> 0 0` からレベルは (2, 0)、n = 2。型 `-> -> int int -> int int` から2つ外した int を int と単一化 |
| 4 | `++` | ⟨`-> int int`, (1, 0)⟩ | 第1引数。`++` のレベルは (1, 0) で一致するので止まる |
| 5 | `*` | ⟨int, (0, 0)⟩ | 第2引数。`*` はオーバーロードあり、レベル (2, 0)、n = 2。型 `-> α1 -> α2 ρ` の ρ を int と単一化した時点で、候補が int 版に絞られて確定し、α1 = α2 = int |
| 6 | `x`、`x` | ⟨int, (0, 0)⟩ | `*` の2つの引数 |

結果：`⟦\ x : int ⟦twice⟨int⟩ ++ ⟦* x x⟧⟧⟧`

### if[1] の結果をその場で適用する

```
++ :: -> 0 0;  ++ : -> int int = \ x : int + x 1;
-- :: -> 0 0;  -- : -> int int = \ x : int - x 1;
ap :: -> 0 0;
ap : -> int int = \ x : int if[1] == x 0 ++ -- x;
```

| 手順 | 読む語 | 期待 | 判断 |
|---|---|---|---|
| 1 | `\ x : int` | ⟨`-> int int`, (1, 0)⟩ | 関数。本体は ⟨int, (0, 0)⟩ |
| 2 | `if[1]` | ⟨int, (0, 0)⟩ | `-> 0 -> N -> N N` に N = 1 を代入してレベルは (4, 0)、n = 4。型は `-> bool -> α -> α α`（α のレベルは (1, 0)）。4つ目を外すために α を `-> β γ`（β のレベルは不明、γ は (0, 0)）に分け、γ を int と単一化 |
| 3 | `== x 0` | ⟨bool, (0, 0)⟩ | 第1引数。`==` はレベル (2, 0) で n = 2。int 版に確定 |
| 4 | `++` | ⟨`-> β int`, (1, 0)⟩ | 第2引数。レベルが一致するので止まる。β = int |
| 5 | `--` | ⟨`-> int int`, (1, 0)⟩ | 第3引数 |
| 6 | `x` | ⟨int, (0, 0)⟩ | 第4引数。レベル宣言の矢印（3つ）を使い切ったので、型から期待を決める（[PAR-6]） |

結果：`⟦\ x : int ⟦⟦if[1] ⟦== x 0⟧ ++ --⟧ x⟧⟧`（省略形では `⟦\ x : int ⟦if[1] ⟦== x 0⟧ ++ -- x⟧⟧`）

### head：パターンの束縛変数の型

```
head[N] :: -> 0 N;
head[N]<T> : -> list<T> T = \ xs : list<T>
    match xs Nil error[N] "head: 空リスト" Cons x _ x;
```

照合により、T のレベルは (0, N) です（`N` と `T`）。

| 手順 | 読む語 | 期待 | 判断 |
|---|---|---|---|
| 1 | `\ xs : list<T>` | ⟨`-> list<T> T`, (1, N)⟩ | 関数。本体は ⟨T, (0, N)⟩ |
| 2 | `match xs` | 対象は ⟨α, (0, 0)⟩ | α = `list<T>` |
| 3 | `Nil` | | D = list。α を `list<β>` と単一化して β = T。list のコンストラクタは2つなので分岐は2つ。b = (0, N) |
| 4 | `error[N] "head: 空リスト"` | ⟨T, (0, N)⟩ | `error[N]` のレベルは `-> 0 N` から (1, N)。n = 1 |
| 5 | `Cons x _` | | 束縛変数 x の型は T（レベル (0, N)）、`_` の型は `list<T>` |
| 6 | `x` | ⟨T, (0, N)⟩ | レベルが (0, N) で一致するので止まる |

結果：`⟦\ xs : list⟨T⟩ ⟦match xs ⟦Nil ⇒ ⟦error[N] "head: 空リスト"⟧⟧ ⟦Cons x : T _ : list⟨T⟩ ⇒ x⟧⟧⟧`

### 期待レベルが分からない位置

```
length :: -> 0 0;
length<T> : -> list<T> int = \ xs : list<T>
    match xs Nil 0 Cons y rest + 1 length rest;

count1 :: -> 0 0;
count1 : -> int int = \ n : int length Cons \ x : int + x n Nil;

count2 :: -> 0 0;
count2 : -> int int = \ n : int length Cons \[1] x : int + x Nil;
```

length の T は照合で決まらないので ‹T› です。呼び出し側では、T を具体化した型変数のレベルは不明になります。

count1：

| 手順 | 読む語 | 期待 | 判断 |
|---|---|---|---|
| 1 | `length` | ⟨int, (0, 0)⟩ | レベル (1, 0)、n = 1。引数は ⟨`list<α>`, (0, 0)⟩（α のレベルは不明） |
| 2 | `Cons` | ⟨`list<α>`, (0, 0)⟩ | レベル (2, 0)、n = 2。`list<δ>` を `list<α>` と単一化 |
| 3 | `\ x : int` | ⟨δ, (0, ?)⟩ | 完全に不明なので関数。b = (0, ?) の末尾を0として (0, 0) |
| 4 | `+ x n` | ⟨ρ, (0, 0)⟩ | 本体。これで δ = `-> int int` |
| 5 | `Nil` | ⟨`list<δ>`, (0, 0)⟩ | Cons の第2引数 |

count2 では、手順3で `\[1]` により b = (1, 0) になります。本体の `+ x` はレベル (2, 0) で n = 1 なので、δ = `-> int -> int int` です。`\[1]` がなければ本体は `+ x Nil` と読まれ、Nil が int でないので型エラーになります。
