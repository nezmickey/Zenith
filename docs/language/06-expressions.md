# 6. 式の形

この章では式の形だけを定めます。この文法は曖昧で、各頭が取る引数の個数と、match の分岐の数は [07](07-parsing.md) の規則で決まります。

```
expr    ::= head arg*
arg     ::= expr
head    ::= literal | ref | lambda | match
ref     ::= NAME ( "[" larg* "]" )? ( "<" type+ ">" )?
larg    ::= NAT | LVAR
lambda  ::= "\" ( "[" larg "]" )? BINDER ":" type expr
match   ::= "match" ( "[" larg "]" )? expr branch+
branch  ::= CTOR BINDER{n} expr          -- n はそのコンストラクタのフィールドの数
```

`[ ]` と `< >` は語の一部です（[02](02-lexical.md) の 2.6）。`ref` の `NAME` は、関数・コンストラクタ・局所変数のどれかを指します。

## 6.1 リテラル

整数・小数・文字列・真偽値のリテラル（[02](02-lexical.md) の 2.4）は、それぞれ int・double・string・bool の値で、レベルは 0 です。

## 6.2 名前の参照

**[EXP-1]**

- 名前が何を指すかは [02](02-lexical.md) の [LEX-18] とスコープ（[03](03-program.md) の [PRG-9]）で決まります。
- 局所変数には `[ ]` も `< >` も付けられません。
- 関数の `[ ]` は [04](04-levels.md) の [LVL-5] に従います。コンストラクタはレベルパラメータを持たないので、`[ ]` を付けるなら空（`[]`）でなければなりません。
- `< >` を付けられるのは、型パラメータを持ちオーバーロードされていない関数と、型パラメータを持つ型のコンストラクタだけです。型引数は全部指定するか全部省略します。省略した型引数は型推論で決まります（[08](08-type-inference.md)）。

## 6.3 ラムダ

```
\ x : int + x 1
\ f : -> T T \ x : T f f x
\[1] x : int + x
```

**[EXP-2]**

- `\` の後に、引数の名前、`:`、引数の型を書き、その後に本体の式を書きます。型注釈は省略できません。
- 引数は本体の中だけで見えます。
- `\[k]` の k は本体のレベルを表します（[07](07-parsing.md) の 7.6）。k は `NAT` か、見えているレベル変数です。
- ラムダは、置かれた位置によって「関数の値」になる場合と、「その場で直後の式に適用される」場合があります（7.6）。

### ローカル変数

レベル0（またはレベル変数そのもの）を求める位置に置いたラムダは、その場で直後の式に適用されます。これが Zenith でローカル変数を作る方法で、専用の構文はありません。

```
\ sq : int * sq sq * x x
// sq = * x x として、* sq sq を計算する
```

重ねると、束縛される値は内側のものから順に後ろへ並びます。

```
\ sq : int \ t : int * sq t + sq 1 * x x
// t = + sq 1、sq = * x x
```

束縛される値（`* x x`）はラムダの外にあるので、その中では束縛した名前（`sq`）は見えません。内側の束縛の値（`+ sq 1`）は外側のラムダの本体の中にあるので、`sq` を使えます。

## 6.4 match

```
match xs Nil 0 Cons x rest + x sum rest
```

**[EXP-3]**

- `match` の後に対象の式を書き、その後に分岐を並べます。
- 分岐は、コンストラクタ名、そのフィールドの数だけの束縛変数、本体の式からなります。
- 分岐の数は、対象の型のコンストラクタの数と同じです。各コンストラクタをちょうど1回ずつ書き、順序は自由です（[07](07-parsing.md) の 7.7）。
- パターンのコンストラクタには `[ ]` も `< >` も付けません。型は対象の式の型から決まります。
- 1つの分岐の中で、束縛変数の名前は互いに異なります。`_` も普通の名前なので、1つの分岐の中で2回は使えません。
- 束縛変数は、その分岐の本体の中だけで見えます。
- `match[k]` の k は、分岐の本体のレベルを表します（7.7）。

コンストラクタが1つしかない型の match は、値を分解するために使えます。

```
match it Item price d ...       // it を price と d に分解する
```

## 6.5 括弧はない

**[EXP-4]** Zenith には、式をまとめるための括弧も、ローカル変数のための専用の構文もありません。式の区切り方はすべて [07](07-parsing.md) の規則で決まります。`(` と `)` は一般の文字で、名前の一部になりえます。
